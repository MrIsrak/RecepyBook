# Подпись релизов

Android разрешает обновить приложение поверх старой версии, только если обе версии подписаны **одним и тем же ключом**. Поэтому релизы нужно подписывать постоянным ключом.

Без секретов workflow `Release` подписывает APK одноразовым debug-ключом. Такой APK ставится, но каждую следующую версию придётся ставить с удалением предыдущей, а вместе с ней удаляются и данные. Перед удалением сделай резервную копию в Настройках.

## Настройка (один раз)

1. Создай ключ (нужен JDK):
   ```bash
   keytool -genkeypair -v -keystore release.jks -alias recepybook \
     -keyalg RSA -keysize 4096 -validity 36500
   ```
2. Закодируй его:
   ```bash
   base64 -w0 release.jks > release.jks.b64
   ```
3. В репозитории открой **Settings → Secrets and variables → Actions → New repository secret** и добавь:

   | Секрет | Значение |
   |---|---|
   | `SIGNING_KEYSTORE_BASE64` | содержимое `release.jks.b64` |
   | `SIGNING_STORE_PASSWORD` | пароль хранилища |
   | `SIGNING_KEY_ALIAS` | `recepybook` |
   | `SIGNING_KEY_PASSWORD` | пароль ключа |

4. Сохрани `release.jks` и пароли в надёжном месте, например в менеджере паролей. **Если ключ потерян, обновлять приложение поверх установленного станет невозможно.**

Никогда не коммить `*.jks` в репозиторий: файл добавлен в `.gitignore`.
